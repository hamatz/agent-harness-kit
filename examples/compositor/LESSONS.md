# Compositor Lessons Learned

Compositor の開発で踏んだ地雷と、その再発を防ぐ仕組みの記録です。記録フォーマットは [`kit/LESSONS.md`](../../kit/LESSONS.md) と同じです。

## 恒久教訓インデックス

### [2026-11-02] 本物の原稿で、表のページまたぎと小見出しの取り残しが見つかった
- Context: 紙面モード（ページ送り）の組版。社内向け冊子の原稿（表5つ・小見出し約30）を A5 横組みで組んだ
- Trap: 既存の8通りの検査にはすべて合格したが、1ページずつ目で見ると、表が2ページに分かれ、小見出しが4か所でページの最下部に取り残されていた。
  検査は「図版・コード図版のページまたぎ」と「章の改ページ」しか測っておらず、検査用の本にも表と小見出しが無かったため、どちらも一度も試されていなかった
- Rule: 表はページをまたがせない。小見出しは続く本文と同じページに載せる。
  横組みは段組みの break-inside / break-after で、縦組みは組版スクリプトの keepTogether で詰め物を入れて次のページへ送る（表は本文の途中へ運ぶと読む順番が変わるので、図版のようには運ばない）。
  検査用の本には、検査したい要素を必ず含める
- Rung: 検査（CI の必須チェック）
- Immunity Test: examples/compositor/tests/verify_layout.mjs（「表がページの境目をまたがない」「小見出しがページの末尾に取り残されない」）、検査用の本の第4章
- Proof: 直す前のツールでは冊子が8通りすべて不合格、直した後は8通りすべて合格。
  examples/compositor/tests/selftest.mjs で、送りを止めた版が縦組み・横組みそれぞれの4通りだけを落とすことを毎回確かめている
- 付記: 検査を足したとき、縦組みでページの境目ちょうど（丸め誤差の範囲）に置かれた表を「またいでいる」と誤判定した。
  ページ番号の計算と同じ許容幅で、ページ内の位置も丸めるよう検査を直した。誤判定を直した後も、直す前のツールが落ちることを確かめてから採用した

### 縦組み紙面で図版がページをまたぐ（論文 第1.4節の事例）
- Context: 紙面モード（ページ送り）の組版。図版・コード図版を本文に回り込ませる処理
- Trap: 図版の前に余白を足して次のページへ押したところ、本文がその余白まで避け、別の図版が境目をまたいだ。
  スクリーンショットで確認しながら直したため、直した崩れが別の修正で崩れ、一部の判型でだけ直っていることもあり、20回以上往復した
- Rule: 図版は余白で押さず、本文中のページの切れ目まで運ぶ。運べないときだけ詰め物を挿む。
  合否は目視ではなく位置の検査で決め、全判型・全組方向（8通り）に掛ける
- Rung: 検査（CI の必須チェック）
- Immunity Test: examples/compositor/tests/verify_layout.mjs、verify_matrix.mjs
- Proof: 8通りすべてで、壊した版が Exit 1 になることを確認済み（examples/compositor/tests/selftest.mjs）

## まだ機械で確かめていないこと

- 印刷（PDF）の改ページ。今回、目次の直後の前付が目次のページ末尾に残る崩れを直したが、確かめたのは目視だけ。検査は画面の紙面モードしか測っていない
- 縦組みの印刷は、画面の紙面モードとページ数が大きく異なる。原因は未調査
